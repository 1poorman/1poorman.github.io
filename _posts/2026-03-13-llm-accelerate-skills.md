## KV Cache

标准注意力计算机制（单个头的输出）：
$$
\text{head}_i = \text{Attention}(Q_i, K_i, V_i) = \text{softmax}\left(\frac{Q_i K_i^\top}{\sqrt{d_k}} + M\right) V_i
$$
如公式所示，每输出一个token，需要获得此刻及之前的K、V矩阵，与当前的Q矩阵点积。在所有的token输出前，K、V矩阵不断累积且可复用，将之缓存可省却大量的计算。
Q则只有当前时刻有效，因此不必缓存。

## 一、 PagedAttention
vLLM 框架的核心创新技术，它彻底解决了大语言模型（LLM）推理中显存碎片化和KV Cache 管理低效的问题。

背景：

为了加速注意力机制计算，LLM通常采用的kv cache，这需需要动态分配显存。但请求长度未知，如果采用默认的提供最大长度的方式，会造成显存浪费以及产生大量无法利用的细小碎片，导致显存整体利用率很低（20%~30%）。

原理：
vLLM 将操作系统的分页思想引入到 GPU 显存管理中。

A. 非连续内存块 (Non-contiguous Blocks)，  化整为零
机制：KV Cache 不再需要连续的显存空间。它将 KV Cache 切分成固定大小的块（Blocks）（例如每个块包含 16 或 32 个 token 的 KV 数据）。
分配：当请求生成新 token 时，系统动态地分配一个空闲的物理块给该请求，而不是预先分配一大块。

B. 页表映射 (Page Table)
机制：维护一个页表（Block Table），记录每个请求的逻辑块（Logical Block）对应哪个物理显存块（Physical Block）。
查找：当 Attention 机制需要访问第 i 个 token 的 KV 值时，通过页表计算出它所在的物理块地址，然后去读取。
灵活性：同一个请求的逻辑块 1、2、3 可以分散在显存的任何位置，只要页表能索引到即可。

C. 共享与写时复制 (Copy-on-Write)
场景：在并行采样（Parallel Sampling，即同一个 Prompt 生成多个不同回答）或多轮对话中，多个请求可能共享相同的前缀。
机制：PagedAttention 允许不同的请求共享同一个物理块（只读）。只有当某个请求需要修改该块（写入新 token）时，系统才会复制一份新的物理块给它（写时复制）。
收益：极大地减少了重复数据的显存占用。

## 二、 Prefix Caching (RadixAttention)
SGLang 的灵魂。它将 LLM 推理从“每次都是全新的计算”转变为“增量计算”，特别适合上下文很长、重复内容很多的场景。如果输入的开头部分（Prefix）之前已经计算过，就直接复用之前的计算结果（KV Cache），跳过重复的矩阵运算，可视作KV Cache的场景拓展。

原理：
预填充（Prefill）：每次输出token的前置步骤，即之前的kv矩阵
在对话场景，System Prompt通常是必须的，每次推理时都会包括这一部分的tokens计算，追问时历史对话也必须包括，这部分计算往往是重复的，因此可以存储备用。

RadixAttention = PagedAttention (显存管理) + Radix Tree (智能缓存索引)：
前缀可以是任意长度，利用基数树（Radix Tree / Trie）数据结构来管理 KV Cache：
1. 插入（Insert）：当一个新的请求进来时，SGLang 会沿着树匹配最长的公共前缀。匹配到的部分直接从显存读取 KV，未匹配的部分（后缀）进行计算，并将新生成的 KV 作为新节点插入树中。
2. 复用（Reuse）：如果下一个请求的前缀与树上某条路径完全重合，直接定位到该节点，跳过所有计算。
3. 淘汰（Eviction）：当显存不足时，SGLang 会根据策略（如 LRU）修剪树的叶子节点，但会尽量保留根部的高频共享前缀（如 System Prompt）。

特点：
1. 任意前缀匹配：不仅能缓存 System Prompt，还能缓存多轮对话的历史、Few-shot 示例、甚至 RAG 检索到的长文档片段。
2. 动态适应：无论用户的输入顺序如何，只要前缀相同，就能命中缓存。
3. 显存高效：相同的前缀在显存中只存一份，多个对话共享同一块物理显存。


## 三、flashAttetion 
Transformer中self-attention 的时间和内存复杂度是序列长度的二次方，序列越长，消耗的内存和时间也越久。

| 版本 | 核心技术实现关键词 | 解决的核心瓶颈 | 硬件目标架构 |
| :---: | :--- | :--- | :--- |
| **v1** | 分块计算 + 在线 Softmax + 重计算 | HBM 访存带宽瓶颈 | Ampere (A100) |
| **v2** | 序列并行 + Warp 分区优化 | GPU SM 利用率不足 | Ampere / Hopper |
| **v3** | 异步流水线 + FP8 块状量化 | 低精度数值稳定性与延迟隐藏 | Hopper (H100) |
| **v4** | 多项式 Exp + 2CTA MMA + CuTe DSL | Shared Memory 带宽瓶颈与 SFU 算力瓶颈 | Blackwell (B200) |

# FlashAttention 技术深度解析与演进 (截至 2026-03-17)
FlashAttention 是一种针对 Transformer 模型中注意力机制设计的**IO感知精确算法**，旨在解决传统注意力机制在处理长序列时存在的计算速度慢与内存占用高的问题。截至2026年3月17日，该技术已迭代至 FlashAttention-4 版本，针对最新的 GPU 架构进行了底层重构。
## 1. 核心原理与技术优势
*   **IO 感知设计**：传统注意力计算需要频繁读写 GPU 高带宽内存（HBM），导致性能瓶颈。FlashAttention 通过**分块计算**，将计算任务分割，在 GPU 片上 SRAM（共享内存）中完成中间计算，大幅减少了对 HBM 的访问次数。
*   **精确计算**：与稀疏或低秩近似方法不同，FlashAttention 在加速的同时保持数值精确，输出结果与标准注意力机制完全一致。
*   **内存效率**：通过避免存储大型注意力矩阵，显著降低了内存复杂度，使模型能够处理更长的上下文序列（如 16K 至 64K tokens）。
## 2. 版本演进与 FlashAttention-4 的重大更新
随着硬件架构的演进，FlashAttention 持续优化，最新的 FlashAttention-4 针对 NVIDIA Blackwell 架构（B200/GB200）进行了彻底重构：
*   **针对 Blackwell 架构优化**：针对新硬件中 Tensor Core 速度极快、但注意力前向传播瓶颈呈指数级增长、后向传播受限于共享内存带宽的不对称扩展问题，重新设计了算法流水线。
*   **性能突破**：通过底层优化，使注意力机制的执行速度几乎达到了**矩阵乘法级**的速度。
*   **关键技术创新**：
    *   **多项式指数模拟**：用于应对 SFU（特殊功能单元）算力瓶颈。
    *   **新型在线 Softmax**：采用条件式 softmax 重缩放，避免了 90% 的 softmax 重新缩放操作。
    *   **2CTA MMA 指令**：允许两个线程块共享操作数，显著减少共享内存流量。
    *   **CuTe-DSL 实现**：采用 CuTe 领域特定语言编写，实现了极速编译。
*   **生态集成与应用**：
    *   **FlexAttention 支持**：FlashAttention-4 已原生适配 PyTorch 的 FlexAttention API。研究人员可以通过几行 Python 代码实现自定义注意力变体（如 ALiBi、滑动窗口等），并由 FlashAttention 后端提供高性能加速支持。
    *   **开源现状**：FlashAttention-4 已于 2026 年 3 月 6 日正式开源，提供完整的算子实现与技术论文，广泛应用于大语言模型训练与推理部署中。
## 3. 核心技术实现深度解析
FlashAttention 的每一次迭代，本质上都是在解决**计算理论与硬件特性之间的错配**。从 v1 的 IO 感知到 v4 的指令级重构，其核心实现逻辑经历了深刻的变革。
### 3.1 FlashAttention-1：IO 感知与分块计算的奠基
**核心突破**：将“内存墙”问题转化为“计算密集型”问题。
**核心痛点与解决思路**：
在传统注意力机制中，$N \times N$ 的注意力矩阵必须写入高带宽内存（HBM）才能进行 Softmax 计算，这导致了 $O(N^2)$ 的内存访问开销。
**实现原理**：FlashAttention-1 引入了**分块计算**与**在线 Softmax**。核心思想是不在 HBM 中存储巨大的中间矩阵，而是将计算任务切分，在 GPU 的片上存储中完成所有中间计算。
**详细实现逻辑**：
*   **分块策略**：
    *   算法将 Query（Q）、Key（K）、Value（V）矩阵切分为小的图块。
    *   图块大小的选择至关重要，必须适配 GPU 流式多处理器（SM）上的 SRAM 大小（例如 A100 的 SRAM 约为 192KB）。
    *   算法通过 CUDA 内核显式控制数据流动，先从 HBM 加载 Q、K、V 的图块到 SRAM。
*   **在线 Softmax 算法**：
    *   传统 Softmax 需要知道全局的最大值和分母和，这在分块计算中是无法直接获取的。
    *   FlashAttention-1 实现了**在线归一化**技术。在计算每一个图块的 Softmax 时，它会动态跟踪当前的“局部最大值”和“局部累加和”。
    *   **数学重缩放**：当算法处理下一个图块时，如果发现新的最大值，它会通过数学公式对之前已经计算好的结果进行“缩放修正”。这使得逐块计算成为可能，且保证了数值精度与全局计算完全一致。
*   **反向传播的重计算**：
    *   为了节省内存，前向传播不存储 $N \times N$ 的注意力矩阵。
    *   在反向传播时，算法利用了 GPU 计算速度快于内存带宽的特性，在 SRAM 中**重新计算**注意力分数 $S$ 和概率矩阵 $P$。这虽然增加了少量的计算量，但彻底消除了巨大的显存读写开销。
### 3.2 FlashAttention-2：并行化与 Warp 级优化
**核心突破**：解决“利用率不足”问题，充分压榨 Tensor Core。
**核心痛点与解决思路**：
v1 虽然减少了 IO，但在 GPU 实际执行时，存在线程束闲置和并行度不高的问题。特别是在长序列场景下，v1 对 Batch 维度的并行依赖较强，导致小 Batch 大序列场景下性能下降。
**实现原理**：v2 调整了并行策略和工作分区，从“块级并行”下沉到“线程级并行”。
**详细实现逻辑**：
*   **序列维度的并行**：
    *   v1 只在 Batch 和 Head 维度上进行并行。v2 新增了**序列长度维度的并行**。
    *   即使 Batch Size 很小，只要序列很长，v2 就能将序列切分给不同的 SM 并行处理，极大地提升了长序列场景下的 GPU 占用率。
*   **工作分区优化**：
    *   在 v1 中，不同的线程束负责计算 K 或 V 的不同块，计算完后需要通过共享内存同步结果。这种同步会产生流水线停顿。
    *   v2 重新设计了分配逻辑：每个线程束负责计算 Q 的一个完整块，内部直接处理对应的 K 和 V 块。这减少了线程束间的通信需求，避免了“等待”带来的算力浪费。
*   **指令级调优**：
    *   针对 Tensor Core（矩阵计算单元）进行了微调，减少了非矩阵乘法指令的开销，使得计算密度更高。
### 3.3 FlashAttention-3：异步流水线与 FP8 精度
**核心突破**：针对 Hopper 架构的“异步计算”特性，解决精度与速度的矛盾。
**核心痛点与解决思路**：
NVIDIA H100 (Hopper 架构) 引入了 FP8 精度和异步指令，但 FlashAttention-2 主要基于 FP16/BF16 设计，无法直接利用新硬件特性。直接使用 FP8 会导致数值溢出（Softmax 中的指数运算范围极大）。
**实现原理**：利用硬件异步特性构建计算流水线，并发明 FP8 专用的量化算法。
**详细实现逻辑**：
*   **异步流水线**：
    *   Hopper 架构允许 Tensor Core 在计算的同时，执行内存加载指令。
    *   v3 实现了**生产者-消费者模型**：一个 Warp 负责从 HBM 异步加载数据到 SRAM（TMA 指令），另一个 Warp 负责在 Tensor Core 上进行矩阵乘法。这使得内存延迟被完全隐藏在计算时间中。
*   **块状量化与 FP8 兼容**：
    *   直接将 FP16 数据转为 FP8 会丢失精度或溢出。v3 实现了**块状量化**。
    *   它为每一个计算块维护一个动态的缩放因子。在计算 $QK^T$ 时，将结果保持在 FP32 精度进行累加（防止溢出），然后在线性缩放回 FP8 进行存储。这种“混合精度”策略在保证数值稳定性的同时，享受了 FP8 双倍的吞吐量。
### 3.4 FlashAttention-4：Blackwell 架构与指令级重构
**核心突破**：针对 Blackwell (B200) 的指令集重构，将 Softmax 逼近 Matmul 速度。
**核心痛点与解决思路**：
截至 2026 年，NVIDIA Blackwell 架构虽然算力爆炸，但硬件扩展逻辑发生了质变：Tensor Core 算力增速远超 Shared Memory 带宽增速。传统的 Softmax 计算流程成为了严重的瓶颈。
**实现原理**：FlashAttention-4 不再仅仅是算法优化，而是涉及到底层汇编指令（SASS）级的重构。
**详细实现逻辑**：
*   **多项式指数模拟**：
    *   在 Blackwell 架构上，硬件自带的 `exp` 指令（SFU 单元）速度相对较慢，无法匹配 Tensor Core 的极高吞吐。
    *   v4 实现了基于**多项式逼近**的指数计算。通过查表和多项式拟合，利用 Tensor Core 本身来近似计算 $e^x$，从而绕过 SFU 的瓶颈。
*   **2CTA MMA 指令**：
    *   这是一项底层汇编级的创新。传统的矩阵乘法累加（MMA）指令由单个 CTA（线程块）控制。
    *   v4 引入了 **2CTA MMA**，允许两个线程块协同加载操作数并直接输入给 Tensor Core。这种机制极大地减少了对 Shared Memory 的读写压力（因为数据可以直接在寄存器层面流转，无需频繁回写 Shared Memory），解决了 Blackwell 架构下的内存带宽瓶颈。
*   **条件式 Softmax 重缩放**：
    *   在 v1 中，每次处理新块都需要对所有旧值进行重缩放。在 v4 中，算法引入了一种新的数学逻辑——**条件式重缩放**。
    *   它通过数学推导发现，90% 的重缩放操作是可以被“推迟”或“合并”的。算法在汇编层面跳过了这些冗余的乘法指令，使得整个 Softmax 流程的指令数大幅减少，性能逼近单纯的矩阵乘法。
*   **CuTe-DSL（领域特定语言）**：
    *   v4 的代码实现从传统的 CUDA C++ 迁移到了 CuTe DSL。这是一种更高层的抽象语言，允许开发者以“张量代数”的形式描述算法，由编译器自动针对 Blackwell 的复杂存储层级（HBM -> L2 -> L1 -> Shared Memory -> Registers）进行最优的映射，消除了手写底层汇编难以维护和移植的问题。
