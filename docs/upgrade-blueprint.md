本次完成的是源码和内容审阅。当前环境未发现 Ruby、Bundler 或 Jekyll 可执行程序，因此尚未运行站点构建、浏览器预览或性能测试；下面的验收项是实施目标，不能当作现状已达标的结论。

**视觉方向采用研究笔记的气质。** 建议以暖白或石墨灰为页面底色，保留青绿作为主要交互色，琥珀色表示进行中的记录。用细分隔线、稳定的排版、少量网格纹理和实验编号组织内容；正文使用易读的中文字体，代码和指标使用等宽字体。明暗两种主题沿用同一套语义颜色。

网站个性应主要来自真实内容：醒目的研究问题、一句话发现、明确的实验条件、可查阅的结果。通用封面逐步替换为与文章相关的结构图、数据图或纯文字摘要。文章阅读区采用安静背景，持续烟花效果转为单独演示入口。动效集中在展开、选中和对比反馈，并响应减少动画的系统设置。

**信息架构围绕发现、阅读和验证展开。** 点击站点名称返回首页，主导航提供「文章、实验、专题、项目、关于」，搜索和主题切换作为工具入口。

| 页面 | 主要内容 | 核心操作 |
| --- | --- | --- |
| 首页 `/` | 研究方向简介、精选实验、近期文章、专题入口、相关项目 | 快速判断站点关注什么，进入一篇值得阅读的文章 |
| 文章 `/archive` | 所有正式文章；卡片展示类型、问题摘要、主题和日期 | 按主题、类型、关键词筛选，切换发布时间或更新时间排序 |
| 实验 `/experiments/` | 从文章数据中筛出实验记录，展示任务、进展和已有结果 | 找到同类实验，进入方法与结果页 |
| 专题 `/topics/` | 以研究问题组织文章、实验和项目，给出阅读顺序 | 从入门背景进入实现、比较和后续实验 |
| 项目 `/projects/` | 现有 4 个项目及其相关文章、实验入口 | 查看项目解决的问题、实现和验证依据 |
| 关于 `/aboutme` | 作者关注的问题、技术方向、GitHub 和 RSS | 了解作者和持续关注方式 |

首页的推荐阅读顺序：简短定位与搜索入口 → 一项精选实验及其发现 → 最近文章 → 专题阅读路径 → 相关项目。文章卡片优先展示内容摘要；实验卡片额外展示任务和条件。实验编号只用于真实实验记录。

现有文章路径继续使用 `/:year-:month-:day-:title/`。归档和标签旧入口保持可用，原有分页地址纳入兼容检查。示例文章退出正式内容导航和搜索，原链接可继续访问。

**内容类型与研究主题分开管理。** 类型回答“这篇内容提供什么”，主题回答“它研究什么”。建议采用三种类型：技术分析、实验记录、工程实践。初始主题可以是模型与视觉、时序建模、Agent 工程、数据系统、开发实践；OCR、SAM、KV Cache 等保留为更具体的标签。

| 字段 | 用途 | 采用方式 |
| --- | --- | --- |
| `kind` | `analysis`、`experiment`、`engineering` | 为正式文章补齐；旧文章缺省时仍能渲染 |
| `topics` | 使用稳定的主题标识，例如 `time-series` | 由 `_data/topics.yml` 维护显示名、说明和排序 |
| `summary` | 一到两句说明问题与主要发现 | 同时用于文章列表、搜索摘要和文章导读 |
| `last-updated` | 最近一次实质性内容修订时间 | 复用现有字段，只在确有更新时填写 |
| `series`、`series_order` | 组织连续研究记录 | 仅在确有阅读顺序时填写 |
| `experiment_id` | 关联结构化实验数据 | 只用于有对应数据的实验文章 |
| 实验进展、结果来源、复现材料 | 区分进行中记录、已完成记录及证据来源 | 放在实验数据中；按实际材料填写，缺少材料时明确显示 |

以现有时序基准文章为例，可补充以下元信息；这是字段示意，尚未修改文章：

```yaml
kind: experiment
topics: [time-series]
summary: 对比时序模型在仿真工况下的预测误差、检测表现、推理延迟和显存占用。
experiment_id: timeseries-anomaly
```

技术分析的导读建议包含研究问题、核心判断、适用条件和参考资料。实验记录进一步包含假设、环境、数据集、方法、结果、解释、局限和下一步。工程实践重点展示要解决的问题、实现步骤、关键配置、失败案例和使用边界。作者继续写 Markdown，页面按已有字段呈现对应组件，避免要求每篇文章填写整套实验表单。

**首个实验样板选用《时序多模型基准：时序异常检测与预测对比》。** 这篇文章已经提供硬件、数据集、评估协议、预测结果、检测结果和通道数消融，信息完整度最高。建议分成以下视图：

1. 实验概览：研究问题、仿真数据来源、测试使用的 RTX 3090 单卡、软件环境和主要发现。
2. 预测对比：选择模型和评估数据段，对比 MAPE、延迟、参数量与显存；提供可排序表格和按指标切换的图表。
3. 消融分析：展示 PatchTST 的 1/4/6 通道结果，并将 GRU、Chronos 的单变量与多变量结果放在各自协议下解释。
4. 检测对比：独立展示检出率、误报率、单窗口延迟和批量开销。
5. 方法与材料：说明评估窗口、测量方式、训练与零样本配置、代码链接，以及当前可提供的结果数据。

预测轨和检测轨使用不同指标与任务，分别呈现。加载显存、单次推理峰值和批量峰值保留各自定义。默认视图只比较条件明确的结果，切换任务或协议时同步更新说明。

源码审阅也发现一个值得在数据迁移时核对的表述：第 6.1.1 节的单通道 PatchTST 缓变故障 MAPE 为 7.13%，第七节仍将 8.44% 写作最佳结果。应明确“既有四通道模型”和“补充消融单通道模型”的比较范围，再生成摘要与榜单。把表格和图表改为读取同一份数据，可以减少后续更新出现这种不一致。

当前博客仓库没有这项实验的原始 CSV、逐点预测、日志或权重，只有文章里的汇总表。首版可支持已有汇总结果的比较与 CSV 下载。时序回放需要补充时间戳和预测序列；阈值调整后重算检出率需要逐点异常分数及标签。这些功能在相应数据可用后扩展，页面同时标明结果来自仿真工况。

第二个样板可以选择 OCR 文章，先建立方案特性比较与原图/输出展示；有成对输出样本后，再加入并排对比。定性分析和实际测量结果各自标注来源。
